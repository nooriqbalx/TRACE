Overview

TRACE targets four vulnerability classes that automated fuzzers cannot find: broken object-level authorization, broken authentication, excessive data exposure, and rate-limiting failures. Each requires reasoning about identity and ownership, not input validation, which is what fuzzers are built to test.

An LLM can reason about these classes from an API's shape, but it hallucinates. It flags endpoints that are not broken and misses behavior that only shows up at runtime.

TRACE's answer: every LLM-proposed finding is gated on a real, replayable probe, then confirmed by an independent, deterministic, LLM-free oracle, before it is ever reported.

What grounding changes

C1 to C2. A generic DAST scanner found none of TRACE-Bench's 16 seeded vulnerabilities. An LLM reasoning over the same spec found 7, with roughly 60 percent of its claims wrong.

C2 to C3. Giving the LLM a real dependency graph, 14 inferred edges including the appointment-to-patient relationship C2 consistently missed, raised precision from 0.41 to 0.57 and cut false positives from 10 to 6.

C3 to C4/C5. Gating every proposed finding on a genuine executed probe eliminates false positives entirely. Precision reaches a clean 1.00 at both stages, at the cost of recall. C4 and C5 can only report what this project has built a working probe or oracle for.

C4 to C5. The deterministic oracle refuted one finding that had already passed grounding, proof the verifier catches cases grounding alone cannot.

How it works

The engine (src/tracesec/) has four layers: ingestion parses an OpenAPI spec and infers dependencies between operations; proposal generates candidate findings, either from a generic DAST scan or an LLM reading the spec; grounding re-anchors every proposed finding to a real probe against the live target; verification dispatches grounded findings to a deterministic, LLM-free oracle. Nothing is reported that TRACE cannot itself replay.

# clone and run the full test suite locally $ git clone https://github.com/nooriqbalx/TRACE.git $ cd TRACE && uv sync $ uv run pytest # 135 tests, full engine, no network or API keys needed
spec.py
Parses an OpenAPI 3.x document into a normalized operation list.
dependency.py
Infers producer/consumer relationships between operations. Falls back to one live probe when a target's schema can't express field names statically.
scope.py
Allowlist-enforced HTTP client. Blocks off-scope requests, including redirect chains.
evidence.py
SHA-256 hash-chained, tamper-evident evidence store. Secrets redacted before anything touches disk.
executor.py
Ties the scope guard to the evidence store, with a per-run request cap and an explicit kill switch.
llm_scanner.py
C2 (LLM-only) and C3 (dependency-aware LLM) proposal stages.
grounding.py
C4. Rejects any finding not backed by a genuine, executed probe.
verifier.py
C5. Deterministic BOLA, excessive-exposure, and unthrottled-burst oracles, plus regression checking.
detection.py
Recognizes TRACE's own attack traffic, enumeration and burst patterns, in the evidence log.

Evaluated against TRACE-Bench: 24 hand-built vulnerable/patched scenario pairs, six per class, each with a code-level toggle and a fully automated ground-truth test, plus decoys designed to catch exactly the false-positive pattern shown in the exhibit above.

Found by hand, first

Every oracle in verifier.py generalizes something reproduced by hand first, against OWASP crAPI, a real, deliberately-vulnerable reference application.

Broken object-level authorization: vehicle location

GET /identity/api/v2/vehicle/{id}/location

A second user's authentication token retrieved another user's live GPS coordinates, name, and email. HTTP 200, no ownership check.

Root cause
The session token carries only a subject and role, no resource-scoping claim. Authorization has to happen at the database lookup, and here it did not.
Fix
Compare the vehicle's owner against the token's subject before returning data.
Detection
Alert when one identity requests many distinct resource IDs of the same shape in a short window. This is exactly what detection.py's enumeration rule automates.

Broken object-level authorization and excessive exposure: mechanic reports

GET /workshop/api/mechanic/mechanic_report?report_id={id}

The identical missing-ownership-check pattern, recurring on a second, unrelated endpoint, plus a phone number in the response that no UI in the app ever displays.

Root cause
Same missing check, different resource. The response also over-serializes fields the caller never needed.
Fix
Ownership check, plus a narrower response serializer.
Detection
Same enumeration signature as the first case. The recurrence across unrelated endpoints is itself evidence of a systemic pattern.

Broken authentication: unthrottled OTP

POST /identity/api/auth/v3/check-otp

A 4-digit one-time code, no rate limit, no lockout. 201 guesses succeeded in roughly 4 seconds, sustained.

Root cause
A 10,000-value keyspace with zero throttling has negligible real security. The full space is exhaustible in minutes.
Fix
Rate-limit by identity and endpoint. Lock out after repeated failed attempts.
Generalized as
verify_unthrottled, a bounded-burst oracle now reused across both broken-authentication and rate-limiting checks in TRACE itself.
